How we build Smart-Clearance in 15 days

A working prototype, not a slide deck: a SvelteKit progressive web app served from Firebase Hosting's CDN, signed in with Firebase Authentication, nudged by in-app push through Firebase Cloud Messaging, with a Python agent service on Cloud Run built on Google's Agent Development Kit, Gemini on Vertex AI doing the reading, pricing and talking, PostgreSQL and BigQuery underneath, and Playwright with Argos guarding every screen.

Where tokens are checkedThe API verifies every request's ID token with firebase_admin.auth.verify_id_token, reads role and org_id claims, and filters queries by them. The agent event stream is read with fetch() and a streamed response body, so the same Authorization header is used; no token ever appears in a URL.
RolesCustom claims set by an admin script (uv run set-role <uid> distributor D-NGP); the client reads them from the token to pick its layout.

Local and CIFirebase Local Emulator Suite (Auth, Hosting) in docker compose and GitHub Actions; Playwright signs in through the emulator with seeded users.
Why not Identity PlatformSame engine, enterprise billing; nothing we need (SAML, multi-tenancy) before the deadline. Upgrade path is a console toggle.

Static assets on a CDNnew in v2

Yes, and it changes the shape of the deployment for the better: the PWA becomes a static build on Firebase Hosting, which is a global CDN with Brotli, HTTP/2, free TLS and per-PR preview URLs. The agents API stays on Cloud Run.

OptionWhat it isVerdict
Firebase Hosting (chosen)Static SvelteKit build uploaded by firebase deploy; served from Google's edge network; cache headers from firebase.json; preview channels for pull requestsFastest to set up, pairs with Firebase Auth and FCM, free at our scale. Preview URLs let Argos screenshot every PR on a real CDN origin.
Cloud CDN + global external Application Load BalancerBackend bucket for /_app/immutable/**, serverless NEG to Cloud Run for the API, Cloud CDN enabled on both, Cloud Armor optionalThe "pure GCP" form; more control (custom cache keys, signed URLs) but about $20 a month for the forwarding rule and a day of Terraform. Documented as the enterprise path; not needed by 17 Oct.
SSR on Cloud Run with Cloud CDNKeep adapter-node and cache rendered pages at the edgeNo benefit for an app whose pages are user-specific; dropped.

What goes where. SvelteKit emits hashed, immutable files under /_app/immutable/: cached for a year at the edge and in the service worker. index.html, the manifest and the service worker are served with no-cache so a deploy reaches users on the next open. API calls and the SSE stream go directly to the Cloud Run URL (CORS) rather than through a Hosting rewrite, so long-lived streams are never buffered by the CDN.

AI and agents: what Gemini actually does

Five real model calls per route run, each with a JSON schema so the output is machine-checkable. The maths (gates, at-risk units, channel economics, allocation) stays deterministic Python; Gemini reads, explains, writes and talks.

AgentModelInputStructured outputFallback
Visiongemini-3-flash-previewCarton label photo + DMS record{batch_no, mfg, best_before, mrp, pack, condition, confidence, mismatches[]}Canned extraction for the demo photo
Valuergemini-3.1-pro-previewComputed channel table, batch facts, tax rules{per_channel_note[], risks[], indicative_flags[]}Template notes
Routergemini-3.1-pro-previewAllocation, alternative, guardrails{explanation, alternative_comparison, push_title, push_body_en, push_body_hi}Template text
Lister + Outreachgemini-3-flash-previewVerified fields, scheme, retailer language{listing_title, description, offer_push_hi|mr|te, offer_page_copy}Template copy

Model policy. Preview models give the best demo; GA Gemini 2.5 Flash sits behind MODEL_TIER=stable so a preview deprecation the week of the demo costs one environment variable. Every call has a 20-second timeout and a deterministic fallback. Temperature 0.2 for structured calls, 0.7 for offer copy.

Agent engine choice. ADK runs inside our Cloud Run service for the whole build because the UI needs the event stream and we need the mocks next to the agents. Deploying the orchestrator to Vertex AI Agent Engine is the stretch goal for day 12.

What happens from the Watcher's morning run to Priya's tap.

2
Notifier

3

5

Progressive web app

One codebase that installs on Priya's Android phone, Rakesh bhai's budget phone, Anita's MacBook and a judge's iPad, keeps working on one bar of signal, and taps people on the shoulder when it needs them.

  • Web app manifest: name, maskable icons, theme colour, display standalone, start URL on the role's home.
  • Service worker (Workbox via vite-pwa injectManifest): precache the app shell; stale-while-revalidate for /api/batches, /api/impact, /api/inbox; network-only for SSE and writes; FCM background handler in the same worker.
  • Push: FCM web push with deep links; permission asked from a button after the first useful moment; inbox as the always-on fallback.
  • Offline state: last dashboard snapshot with an "offline, showing 09:12 data" banner; Route, Approve and Order disabled until back online; photo uploads queued with Background Sync where supported.
  • Install: prompt on Android and desktop Chrome; Safari gets the "Add to Home Screen" hint on iOS, which also unlocks push there.
  • Responsive: phone, tablet and desktop layouts; the Route Room stacks timeline over money panel on phones; touch targets 44 px.
  • Dark mode from the OS plus a toggle; Hindi and Marathi text in Noto Sans Devanagari served from the CDN.
  • Lighthouse CI budget on the preview URL: PWA installable, performance ≥ 85 on mobile, accessibility ≥ 95.
